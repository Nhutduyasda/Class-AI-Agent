# Work-only Gate3 execution architecture

Owner decision on 2026-10-29 supersedes Windows-local production as the selected direction. There is no personal-computer handoff. Windows11/portable-tools/F: USB/ACL acceptance is NOT a prerequisite for this architecture, and no Linux result is called Windows PASS. The old Windows route remains historical, unaccepted and unused.

## Selected direction and actual deployment state

Prepare a portable cloud coordinator plus a minimal credential-bearing child process for a future independently reviewed immutable cloud host. A protected, manually authorized GitHub Actions Linux runner is the candidate existing-service host. No workflow is installed, dispatched, scheduled, merged or deployed in this task. GitHub included compute/storage exposure and entitlement are UNKNOWN; no Windows CI or other billable CI was triggered. ChatGPT Work scratch remains development/test storage only, never production durability or credential authority.

The new `scripts/auto-factory/cloud/` is separate from Gate2's deliberately OFFLINE_SIMULATION_ONLY contracts. It does not relabel test refs as production. The public feature branch is only review source: it is not a credential executor, private media destination or checkpoint authority.

The production design needs two existing, explicitly approved private repositories with protected state branches, externally pinned genesis commits and independent administrative/control arrangements. No such stores are selected/provisioned here, and no unrelated repository is used. The primary retains append-only event history and private WAV/receipt objects; the secondary acknowledges checkpoints and retains identical private evidence. Both must support no-force/no-delete/admin-enforced protection, least-privilege access and independent backup/restore evidence. Git history from each externally pinned root detects a normal fast-forward restoration of old journal/checkpoint content, including a simultaneous restoration of both current files. Missing/incomplete/nonlinear/deleted history blocks operation. This does NOT protect against a compromised provider or administrators who can secretly remove history/change protection; separate verified control/retention is mandatory. Two directories, two writable refs, or two repos under an unverified common authority do not establish independence.

The concrete GitHub REST adapter performs private-repo and protection checks, conditional blob-SHA updates, immutable readback and bounded blob reads (including Contents responses above1MB via Git Blobs). It creates neither repositories nor branches and never force-updates a ref or retries a failed write. Runtime adapter code is implemented; actual remote persistence/privacy/protection/restore has NOT been accepted. Tests use disposable in-memory remote-port fixtures, not live private repositories.

## Trust boundary

A protected host must load a read-only immutable code/dependency snapshot before any key release, verify the exact Node/source/lockfile/dependency build digest, and pin external owner/reviewer Ed25519 public keys and the exact state-store roots. A repository cannot choose its own trust roots, code identity or approval. Signed grants bind the exact V2 byte/payload/SSML identities, reviewed build, fixed Azure resource/region, independent evidence digests, opening liabilities, tax-inclusive maxima, twelve identities, one attempt and a maximum15-minute window. Different owner/reviewer keys are required. Cryptographic signatures authenticate an externally provisioned signer; they do not make self-authored accounting, storage or review fixtures true.

`cloudPilot` validates build/input/grant before use, refuses implicit state initialization, checks signatures/expiry before each dispatch and serializes RESERVED -> DISPATCHING -> RETAINED with remote acknowledgement. A reserved or dispatching attempt blocks later paid execution after restart; there is no run-ID/epoch escape or automatic retry/reconciliation. A provider timeout, invalid response or failed receipt/backup acknowledgement stops the pilot. Retained results are hash-verified in both stores and reused without synthesis. Receipts distinguish response provenance from actual invoice: reserved tax-inclusive maxima remain possible liabilities until independently reconciled. No historical estimate is refreshed by changing dates.

The Azure child receives only the exact allowlisted request via stdin and a key through an inherited private pipe, with a minimal environment. No key appears in arguments/config/renderer/npm/Git. The child fixes endpoint/region/output, checks the immutable12-identity allowlist, performs one HTTPS POST without redirects/retries, and emits only bounded verified response data or a fixed error. Lookup and network timeouts stop; key buffers are wiped where possible. JavaScript string copies and same-UID process inspection are residuals requiring host-level isolation and dump/trace controls. A child process is NOT an OS sandbox.

The reviewed host/bootstrap, secure Azure credential supplier, read-only mount, OS identity separation, signer enrollment, deployment protection and authenticated data-store binding are NOT configured. `Trust`, clock and adapters are library arguments for controlled host integration/testing; they must never be accepted from browser/PR/request payloads. This implementation is not an independently certified production appliance. Do not instantiate live transports on this PR checkout.

2. Authenticated external owner and independent reviewer authority bound to the image/build, script bytes, canonical payload, plan bytes and all12 request hashes; current expiry and cancellation/kill-switch procedure.
3. Secure host-scoped credential connection to the existing `english-journey-namminh` resource in southeastasia, with authenticated resource/voice catalogue evidence; no key in chat or PR.
4. Existing no-additional-cost runner entitlement and billable exposure proven before CI activation. No inherited PawAI compute approval is applied to this project.
5. Two explicitly scoped private durable stores and externally pinned roots; complete protection/writer/administrator/privacy evidence, independent retained high-water history and hash-preserving restore under disposable storage-failure tests. Same-provider correlated outage/administrator risk must be stated and addressed by the accepted recovery plan.
6. Current account-specific price/tax/balance/outstanding liabilities and worst-case twelve-request cost within AzureUSD0.03/aggregateUSD0.08/productionUSD8/reserveUSD2. Account evidence must be genuine, not signed fixture values.
7. Remote integration/fault tests, actual12/0 evidence, one-attempt ambiguity latch and independent credential-bearing code/host review. Memory-port tests alone are insufficient.
8. Only after1–7 pass: authorized real neutral6/dynamic6 audition; genuine WAV/receipt/provenance and private backup; measured captions/render/full media QA; owner creative review remains separate.

No Windows tests are required for a Linux-only selected host. If Windows support is later claimed it needs its own actual Windows test evidence; this architecture does not issue that claim.
