## Durable ledger without new cloud infrastructure

Proposed authority: dedicated protected `factory-ledger` Git branch in the existing repository, created only in a later authorized gate. It holds an append-only non-secret event journal, daily-slot index, topic hashes, policy epoch, balance projection, attempt states and review index. Existing historical ledgers stay immutable. Gate 0 creates no ledger branch. Git persistence is chosen over ephemeral runner files, cache or expiring workflow artifacts; it still depends on repository availability and protection and is not tamper-proof against repository administrators.

Before every paid call: fetch authoritative ref; validate complete journal/hash chain and policy; atomically claim localDate/runId and reserve the request ceiling in one new commit; push with expected-parent compare-and-swap, without force; fetch and verify the exact committed reservation. On conflict reload/recompute; NEVER send before confirmed reservation. At dispatch, persist DISPATCHING with attempt=1 and readback before sending. Reserve-to-dispatch crash wastes allocation conservatively, never permits another attempt. Crash after dispatch or before receipt commit is ambiguous; quarantine any response and freeze further paid calls. Cancellation does not release the slot/reservation. A known NOT_SENT request may be released only by explicit evidence-backed reconciliation; any uncertain call remains charged at its reserved ceiling until billing resolves it. Settlements append events, never edit/delete prior entries. Persist response hash/receipt before advancing to the next paid request. No automatic retry, provider failover or split fallback.

CAS prevents competing writers from overspending a shared projection; Actions concurrency is only an extra guard. Attempt IDs include policy epoch/run/scene/provider and cannot be reused under another run ID to bypass ambiguity. A global unresolved-attempt latch blocks further paid calls. Test two jobs racing and runner destruction after EACH durable boundary. Missing branch, corrupt history, ref rollback, unexpected writer or unavailable storage blocks all paid work. Keep an owner-held last accepted commit checkpoint; Git ancestry plus that checkpoint detects rewind on recovery. Later configure branch protection against deletion/force pushes and backup/export outside the runner. No guarantee that an administrator cannot remove history. If protection, persistent write permission or rollback detection cannot be provided, unattended paid production is NO-GO; use owner-reviewed offline work until resolved.

## Credentials and trusted execution

Proposed environments: `factory-offline` has zero secrets; `factory-production` restricts deployment to a reviewed protected production branch; `factory-publication` is NOT created and has no credentials. Integration and Video 05 branches remain untrusted for production until separately reviewed/promoted. A future trusted workflow is dispatch-only initially; no schedule in Gates 0–3. GitHub schedule generally executes from default branch, while this engine is absent from main: future activation needs an explicitly approved default-branch control workflow or another owner-approved scheduling arrangement. Do not retarget this PR to solve scheduling.

Proposed environment secret names: AZURE_SPEECH_KEY, optional LLM_API_KEY only if a provider is approved, and FACTORY_LEDGER_TOKEN only if scoped built-in token permissions cannot satisfy protected branch writes. Values are never read or created in Gate 0. Prefer a short-lived narrowly scoped GitHub App token if an existing approved installation can supply it; do not create one now. Verify repository plan/environment/branch-protection capabilities and exact permissions in Gate 2; no claim these settings currently exist. No broad personal token fallback. Region/resource/endpoint and spending policy are non-secret reviewed configuration, not caller-controlled URLs.

Secrets are injected into one dedicated trusted request step via process environment, never arguments, JSON, prompt, logs or media. Map AZURE_SPEECH_KEY to the existing adapter's SPEECH_KEY only inside that process. No daily hidden prompt. This differs from historical PowerShell launchers, which remain for manual use. Disable shell tracing, debug env and process dumps; forbid printing raw SDK errors/responses or environment. Redact by allowlisting diagnostics, not masking alone; transformed keys may evade masking. Never upload home directories, environment files or raw HTTP bodies as artifacts.

Credential jobs must not execute PR/fork code, pull_request_target code checkout, untrusted reusable workflows, caller-selected refs, downloaded executables, package lifecycle hooks, generated scripts or LLM-supplied commands. Pin reviewed code commit and external Actions by full SHA; verify workflow/code/policy digest match. Build/install/test in a secretless job with frozen lockfiles and scripts disabled as appropriate, review dependencies before execution, then pass only bounded schema-validated data to the minimal credential job. Synthesis and Git journal writer tokens belong in separate minimal steps/jobs where practical; renderer/ASR gets neither. No reusable caches writable by untrusted jobs in credential execution. Generated SSML is escaped and voice/endpoint allowlisted. Use a fresh hosted runner; no untrusted persistent self-hosted runner. Restrict workflow/ref edits and production approval permissions. Gate 2 must demonstrate isolation rather than assume it from environment names.

Initial paid pilot requires environment reviewer approval. Removing per-run review for daily operation is a separate owner decision after trust controls pass; credentials can be unattended without allowing arbitrary code or arbitrary spending. Kill switch is a reviewed disabled policy checked before each request, plus disable workflow/environment access; removing credentials alone does not revoke in-flight requests.

## Risk register

| Risk | Severity | Required mitigation / residual limit |
|---|---|---|
| Runner crash loses local attempts | Critical | Durable CAS journal/readback before paid call; ambiguity latch; local ledger alone insufficient. |
| Malicious branch/dependency exfiltrates key | Critical | Trusted immutable executor, environment restrictions, no PR secrets, no install with credentials. Compromised trusted code remains a risk. |
| Actual bill exceeds quote | High | Conservative service maxima, current pricing, liability reconciliation; application cap is not a billing guarantee. |
| Invalid English/unnatural voice routing | High | Explicit spans, approved pilot script, human teaching/listening review; no automated semantic certification. |
| Windows-only render and drifting Python/model dependencies | High | Separate generic renderer, pinned browser/models/imports and cross-platform offline smoke test. |
| Artifacts expire or historical media unavailable | High | Existing durable media destination must be identified and retention verified before paid pilot; Actions artifacts alone are temporary delivery, not authoritative ledger. No destination currently verified. |
| Automated scheduling absent from main | High | Gate 4 requires approved control-plane integration; never silently merge entire stack. |
| License/runner quota | Medium | Asset license manifest, verify Remotion applicability and hosted minutes/storage limits before live operation; no cost-free claim. |
