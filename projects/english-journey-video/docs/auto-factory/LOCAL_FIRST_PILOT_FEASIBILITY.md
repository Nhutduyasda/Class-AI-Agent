# Local-first Windows pilot — feasibility only

Decision: FEASIBLE IN PRINCIPLE AFTER IMPLEMENTATION/REVIEW; CURRENT EXECUTION NO-GO. No local paid executor is enabled, run or certified by P1.5. Existing Azure resource/voices may be reused only under a new explicit, unexpired authorization. No new credential or resource is requested here.

A local machine can remove the need to expose an unauthenticated dashboard or use an unprotected GitHub feature branch as a credential executor. It does not remove Gate2's accounting/trust/recovery requirements. Existing Start-BilingualVoice.ps1 has a hidden credential prompt, plan-specific policy and historical one-attempt behavior; its file ledger alone does not demonstrate the production Git journal/checkpoint, global liability latch or rollback protection required by this factory. Gate2's GitLedger accepts isolated local bare test repositories and test-* refs; its executor only accepts module-owned mock providers. Neither becomes a production adapter merely by moving it to Windows or renaming a ref.

Required implementation and acceptance before even one local paid pilot:

1. **Trusted code**: owner selects an immutable reviewed runtime commit, reviewed preparation/adapter commit, lockfiles and policy digests. Clean isolated checkout; frozen dependency installation without lifecycle scripts in a credential-free phase. No automatic git pull, package install or generated command during credential execution. Recheck exact code/dependency hashes and clean tree before each request. The current feature branch is not a credential trust anchor.
2. **Real approval**: a separately retained owner authorization identifies selected V1 OR V2 file hash, canonical speech hash, exact SSML plan hash and per-request SSML hashes, exact voices/resource/region, count, attempt=1, price/tax basis, maximum Azure/all-service microUSD, expiry and policy epoch. The repository cannot grant itself approval. Capture actual opening balance/liabilities across prior production; retain USD2 reserve and USD8 allocation, not a new reset balance.
3. **Credential isolation**: reuse the existing resource credential only within a minimal reviewed local synthesis process using a hidden prompt or a separately reviewed Windows Credential Manager route. Do not persist plaintext keys, pass them as command arguments or give them to Git/render/install/ASR. No fallback to plaintext credential storage; allowlisted errors only. Credential retrieval and provider catalogue check remain unimplemented/unverified for this new adapter; no key is accessed now.
4. **Durable accounting authority**: a separately authorized production-capable journal adapter must preserve Gate2's append-only hash chain, stable IDs, expected-revision CAS, acknowledged reservation and acknowledged DISPATCHING before send, aggregate budget and unresolved-attempt latch. Use verified durable storage and independently retained checkpoint/backup outside the writable execution directory, with restore/rollback detection. Another file on the same rollback-prone disk is not independent evidence. If using GitHub as durable authority, protected-ref permissions and scoped authenticated writes still need approval/verification. No production ledger ref is created here. A local-only authority would need separate owner-approved threat model, Windows fsync/atomic-write/locking tests and independent crash/rollback recovery evidence; current test refs do not establish it.
5. **Receipt and ambiguity recovery**: one attempt per request, sequential. Persist verified WAV/receipt/hash and read back before the next request. Timeout, crash, missing receipt, failed durable readback or unknown result halts every further paid call. Keep reservation/possible liability; no automatic retry, new-run-ID escape, provider switch or split fallback. A known NOT_SENT conclusion needs evidence; uncertain charges require billing reconciliation appended to history. Audio that succeeded but was not acknowledged must be quarantined, not synthesized again. A refund/credit never follows merely from disabling the runner.
6. **Private retention**: select exact owner-controlled directory, ACLs, durable backup destination and retention period; test hash-preserving restore of WAV, approval, ledger/checkpoints, receipts, SSML, captions, render and review records. Local temporary paths and public GitHub artifacts are not approved retention. Confirm code/font/media licenses and account rights for the intended use.
7. **Windows verification**: Windows11/PowerShell/Node/FFmpeg versions pinned and measured, Unicode paths, hidden prompt behavior, secret-free logs, invalid policy, expired pricing, wrong code/hash, racing processes, storage unavailable/rollback, process termination before/after each durable boundary, ambiguous HTTP results and exact cache reuse. First use mock transport/fake canary only. Real provider transport must receive separate review and owner authorization; present Linux mocks are not Windows execution evidence.

**No-retry operator procedure**: stop executor and prevent later dispatch; retain journal/checkpoint/WAV/receipt unchanged; record last acknowledged boundary and affected attempt IDs; compare local receipt/source hashes with provider usage/billing using the owner's account outside this task; append an evidence-backed settlement/reconciliation; keep uncertainty reserved until resolved; only a new explicitly reviewed authorization can permit subsequent requests. A network failure does not prove NOT_SENT.

Candidate choice and spending permission are separate. Approving a script is not approving 12 requests. Approving a cost ceiling is not approval to bypass missing durable storage. Hosted and local paths remain NO-GO until their own prerequisites pass. Do not run the historical launcher as a shortcut to this factory's paid pilot.
